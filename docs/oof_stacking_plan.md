# Out-of-fold stacking fix

The submitted solution used a late-stage meta-classifier trained on predictions from several model families. During review, I identified a validation issue: some meta-classifier features were generated by models that had already seen the same rows during training or early stopping. Those are in-sample predictions, not true out-of-fold predictions, so the meta-classifier validation score was too optimistic.

This document describes the intended fix.

## Problem

For a 5-fold model family, predicting every row with all five trained fold models creates leakage:

- for each row, four models were trained on that row;
- the remaining model may have used that row for validation or early stopping;
- the meta-classifier learns from overconfident probabilities;
- model-family weights can become unreliable.

## Correct validation design

Use one shared split file for every model family.

Required artifacts:

- `folds.csv` with columns `uid`, `is_pathologic`, `fold`;
- one OOF prediction table per model family, for example `oof_cnn_similarity.csv`;
- optional hold-out split that is never used for model selection.

The OOF table should contain exactly one prediction per training row and model family:

| uid | is_pathologic | p_cnn_similarity | p_antspyx | p_profiles |
| --- | --- | --- | --- | --- |
| example_uid | 0 | 0.123 | 0.151 | 0.098 |

## Procedure

1. Create `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)` once and save the mapping from `uid` to `fold`.
2. Train each model family using the same fold mapping.
3. For fold `k`, train on rows where `fold != k` and predict only rows where `fold == k`.
4. Concatenate the validation predictions from all folds into one OOF table.
5. Train the meta-classifier only on the OOF predictions.
6. Compare on a clean hold-out set:
   - single CNN;
   - mean of fold models;
   - weighted average;
   - OOF-trained stacking.



## Current repository status

The repository keeps the original competition inference code in `code_execution/`. The private competition data and trained weights are intentionally not committed. Because those artifacts are required to retrain the model families, this repo documents the validation issue and the planned OOF repair rather than recomputing the full experiment.
